Computer Vision: A PyTorch Model Trained on the Stanford Cars Dataset

AI and Machine Learning · Ankush Arya · May 11, 2024

Building a TinyVGG architecture with PyTorch and training it on 16,185 car images across 196 classes, from dataset loading to model evaluation

View on GitHub

Introduction

In the rapidly advancing field of computer vision, new breakthroughs constantly reshape the boundaries of what is possible. Among these milestones is the creation of a PyTorch framework. In this article, I detail the development of the TinyVGG architecture and its training on the Stanford Cars dataset, uncovering the implications for vehicle recognition and the practical lessons learned along the way.

Data

The Stanford Cars dataset provides a rich collection of car images for machine learning tasks. It contains 16,185 images across 196 different car classes. Each class typically represents a specific make, model, and year of a car, ensuring detailed classification.

The dataset is split for training and testing, with nearly equal portions of 8,144 and 8,041 images respectively. This split allows researchers to train models effectively and evaluate performance on unseen data.

Dataset Class and Transforms

The StanfordCarsCustom class manages image datasets through structured access and handling of image data. Error handling ensures robustness, enabling seamless data loading even when files are corrupted or missing. Custom transformations (resizing, RGB conversion, and data augmentation) tailor the dataset to the model's needs.

class StanfordCarsCustom(Dataset):
    """Custom Image Dataset for PyTorch."""

    def __init__(self, annotations_file, transform=None) -> None:
        self.annotation_df = pd.read_csv(annotations_file)
        self.transform = transform
        self.classes = self.annotation_df['class_name'].unique()
        self.logger = logging.getLogger(__name__)

    def __len__(self) -> int:
        return len(self.annotation_df)

    def __getitem__(self, idx: int):
        try:
            img_path = self.annotation_df.loc[idx, 'image_path']

            if img_path is None:
                raise Exception(f"Failed to read image: {img_path}")

            image = Image.open(img_path)
            class_name = self.annotation_df.loc[idx, 'class_name']
            class_index = self.annotation_df.loc[idx, 'class_index'] - 1

            class_dict = {
                'class_name': class_name,
                'class_index': class_index
            }

            if self.transform:
                image = self.transform(image)
            return image, class_dict

        except Exception as e:
            self.logger.error(f"Error loading image: {img_path} - {e}")
            return None, None

Training

Two critical components drive training and evaluation: the TinyVGG architecture and the training/testing step functions. The TinyVGG class defines a compact neural network inspired by the VGG model, comprising convolutional and pooling layers followed by a classifier, offering a balance between efficiency and performance for image classification.

The train_step and test_step functions orchestrate the forward pass, loss calculation, and optimisation steps, ensuring efficient model training and evaluation on each epoch.

Model Evaluation

The training curves tell an encouraging story. The loss curve trends consistently downward across epochs, indicating the model is improving its fit to the training data. The accuracy curve trends upward in parallel. The model's ability to correctly classify car makes, models, and years improves with each cycle.

A loss curve that falls and an accuracy curve that rises are necessary but not sufficient. The real test is always generalisation to unseen data.

Performance on training data does not guarantee performance on unseen examples. Evaluating against the held-out test split of 8,041 images gives a clearer picture of how well the model generalises beyond what it was trained on.

Next Steps

  2. Experiment with other architectures: explore alternative computer vision models beyond TinyVGG to evaluate performance trade-offs.
